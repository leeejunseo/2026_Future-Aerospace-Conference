# 회전 우주 파편 포획 시뮬레이터

회전하는 우주 파편을 포획할 때 **대상의 회전 속도와 질량에 따라 로봇팔 · 그물 · 작살 중 어떤 방식이 유효한지**
PyBullet 물리 시뮬레이션으로 정량 비교한다. 이번 단계는 **포획 순간만** 다루며 접근 궤도 계산은 범위 밖이다.
서비스 위성 1기가 이미 목표 근처에서 랜데부를 마친 상태에서 시작한다.

성공은 **대상과 서비스 위성의 상대 각속도가 1 deg/s 이하로 떨어지고, 그 상태가 3 초 이상 유지되며 결합이 끊기지 않는 것**으로 정의한다.
성공률은 어떤 경험식으로도 계산하지 않고 전적으로 물리 시뮬레이션 결과에서 집계한다.

## 빠른 시작

PyPI 의 `pybullet` 은 최신 파이썬(3.12+)용 윈도우 휠이 없어 conda-forge 를 쓴다.
이 PC 에는 `debris-sim` 이라는 이름으로 이미 만들어져 있다.

```bash
conda create -n debris-sim -c conda-forge python=3.12 pybullet
conda activate debris-sim
pip install "numpy<2.5" matplotlib   # conda-forge numpy 2.5 는 BLAS DLL 문제로 행렬곱에서 크래시한다
```

기본 `python`(3.13)에는 PyBullet 이 없으므로 반드시 환경을 활성화하거나 환경의 파이썬을 직접 지정한다.

```powershell
conda activate debris-sim
python capture_sim.py --method arm --target medium --spin 10

# 또는 경로를 직접 지정
& "C:\Users\User\anaconda3\envs\debris-sim\python.exe" capture_sim.py --method arm --target medium --spin 10
```

## 연구 수행 절차

### 1. 계산 실행

```bash
bash run_all.sh 11          # 워커 11개로 전체
bash run_all.sh 11 grid     # 단계 선택: grid | compare | verify | sens
```

세 단계 모두 `--resume` 을 지원하므로 중단 후 같은 명령을 다시 실행하면 이어서 진행한다.
한 단계가 실패하거나 중단되면 다음 단계로 넘어가지 않고 전체가 멈춘다.

12스레드 노트북 기준 예상 소요다. 그물 시행 하나가 감속까지 100 초 규모를 돌기 때문에 전체가 길다.

| 단계 | 시행 수 | 예상 소요 |
|---|---|---|
| 격자 실험 | 4320 | 약 13시간 |
| 방식 간 통계 비교 | 계산 없음 | 수 초 |
| 수치 검증 | 12 | 약 1시간 |
| 민감도 분석 | 1422 | 약 6시간 |

### 2. 보고서 생성

계산이 끝나면 아래 한 줄로 논문용 표와 수치가 정리된다.

```bash

```

`report/report.md` 에 방식·질량별 종합표, 성공률이 꺾이는 회전 속도, 민감도 상위 항목,
그림 캡션 초안, 방법론에 적어야 할 항목이 정리된다.
`report/assumptions.tsv` 에는 가정값 **146개**가 전부 들어가며 그중 **81개가 출처 확인이 필요한 값**으로 표시된다.
이 표는 결과가 없어도 언제든 생성되므로 논문 부록에 바로 쓸 수 있다.

```bash
python make_report.py --only assumptions
```

원고는 두 벌이며, 모든 결과가 채워져 있고 본문 수치는 원자료와 대조를 마쳤다.

| [manuscript/원고_초안.md](manuscript/원고_초안.md) | 모든 분석을 담은 전체판. 발표 준비·질의응답 자료 | 약 17쪽, 표 7·그림 6 |

두 원고 모두 한글 템플릿의 장·절 구조와 서식 지시를 그대로 따른다. 한글에서 템플릿을 열고 옮겨 붙인 뒤
대괄호 안의 서식을 지정하면 된다. 그림은 `manuscript/figures/` 에 번호순으로 준비되어 있다.

참고문헌 12편은 서지사항을 직접 확인해 채웠다. 목록과 각 문헌에서 인용한 수치는
[manuscript/참고문헌.md](manuscript/참고문헌.md) 에 정리되어 있다.

문헌에서 확인한 값 중 본 연구의 설정을 직접 뒷받침하는 것은 두 가지다.

- **회전 속도 범위 0~30 deg/s.** 베른 대학교 천문연구소의 광도 곡선 관측에서 GLONASS 궤도 물체군의
  겉보기 각속도가 1.1~42.2 deg/s 로 분포했고, Envisat 의 자전 주기가 약 12초(= 30 deg/s)로 측정되었다.
- **작살 발사 속도.** RemoveDEBRIS 의 궤도상 실증값은 20 m/s 다. 본 연구의 기본값 12 m/s 는 보수적이며,
  민감도 분석 범위를 8~20 m/s 로 두어 실증값을 포함시켰다.

반면 우주 구조물 표면의 반발계수·마찰계수, 그물 소재의 면밀도, 로봇팔 제원, 작살 고정부 파단력,
테더 윈치 제원은 신뢰할 만한 출처를 찾지 못했다. 이들은 가정값임을 명시하고 민감도 분석으로 견고성을 보인다.

## 격자 실험

회전 속도 0~30 deg/s(2 간격, 16수준) × 질량 3구간 × 방식 3종 × 반복 30회 = 4320 시행을 병렬로 실행한다.

반복마다 실제 임무에서 불확실한 양을 시드로 섭동한다. 회전축 추정 오차 10도, 회전 속도 오차 5 %,
횡방향 상대 위치 오차 0.1 m, 잔류 상대 속도 0.02 m/s, 서비서 지향 오차 1도, 초기 자세 10도다.
같은 반복 번호는 모든 조합에서 같은 시드를 쓰므로(공통 난수) 방식 간 비교가 짝지어져 분산이 줄어든다.

```bash
python run_grid_experiment.py --workers 11 --resume
python run_grid_experiment.py --plots-only                              # CSV 로부터 요약·그래프만
python run_grid_experiment.py --spins 0 10 20 30 --repeats 3 --out quick  # 빠른 확인용
```

출력은 `results/` 에 쌓인다.

| 파일 | 내용 |
|---|---|
| `results_raw.csv` | 시행별 원자료 |
| `results_summary.csv` | 조합별 성공률 + Wilson 95 % 신뢰구간 + 보조 지표 |
| `heatmap_success.png` | 방식별 회전속도 × 질량 성공률 |
| `heatmap_final_rel_omega.png` | 잔류 상대 각속도 중앙값 |
| `heatmap_capture_time.png` | 감속 소요 시간 중앙값 |
| `heatmap_impulse.png` | 최대 충격량 평균 (2차 파편 위험) |

| `experiment_config.txt` | 그 실행에 실제로 적용된 모든 설정값 |

성공률만 보면 "거의 감속했다"와 "전혀 안 됐다"가 구분되지 않으므로 잔류 각속도 히트맵을 함께 본다.

## 모델링

### 공통

중력은 0 이고 서비스 위성(1000 kg 가정)은 자유 부유한다. 포획 반동이 그대로 자세 변화로 나타난다.
시뮬레이션 좌표계는 고도 500 km 원궤도의 LVLH 프레임(x: 진행 방향, z: 천정, y: 궤도면 수직)으로 해석하고,
각 강체에 Hill(Clohessy–Wiltshire) 방정식의 겉보기 가속도와 중력구배 토크 3n²(r̂×Ir̂)를 매 스텝 외력으로 적용한다.
`--no-orbit` 으로 끌 수 있다. 포획 구간에서 효과는 mm~cm, mN·m 수준으로 작지만 실제 궤도 환경을 재현한다.
회전좌표계라 관성 각속도와 상대 각속도가 궤도 각속도(0.06 deg/s)만큼 다르며, 판정 임계값 1 deg/s 대비 무시 가능하다.

### 대상 파편

소형 정육면체(10 kg), 중형 본체+태양전지판(500 kg), 대형 원통(2000 kg)이다.
관성텐서는 해석식으로 계산해 명시적으로 설정한다.
회전은 주축 회전(`principal`) 또는 각속도 벡터를 장동각만큼 기울인 토크-프리 세차(`precession`)를 지원한다.
각감쇠를 0 으로 두어야 각운동량이 보존되므로 `CONFIG` 에서 0 으로 고정했다.

### 로봇팔

6관절과 그리퍼를 역기구학으로 추종한다. 예비 접근점 → 대기점 → 파지점의 3단계로 접근하며,
관절 보간이 호를 그려 대상을 관통하지 않도록 목표점을 데카르트 직선으로 보간하고 접근 원뿔 60도를 둔다.
파지는 고정 제약으로 모델링하되 그리퍼 닫힘 시간 동안 힘 한계를 0 에서 유지력까지 올리는 순응 파지다.
한 스텝에 강체로 붙이면 비물리적 충격이 생긴다. 유지력을 넘으면 미끄러지고, 파지점 이탈 거리로 놓침을 판정한다.
파지 후 관절은 토크 제한 브레이크로 잠근다.

### 그물

9×9 질점을 인장 전용 Kelvin-Voigt 스프링(구조 + 전단)으로 연결한다.
접힌 상태로 발사되어 모서리 추의 측방 속도로 비행 중 전개되고, 첫 접촉 후 둘레 스프링의 자유 길이를 줄여 조인다.
모서리 4점이 서비스 위성과 테더로 연결된다.

**질량은 면밀도 × 면적으로 대상마다 달라진다.** 질점 질량을 고정하면 작은 그물이 비현실적으로 무거워진다.
그물 질량이 대상마다 달라지면 고정 스프링 계수로는 명시적 적분이 발산하므로,
강성과 감쇠를 안정조건(`k ≤ 0.25·m/dt²`, `c ≤ 0.5·m/dt`)에서 유도한다.
그물실은 안정조건이 허용하는 한 비신축성으로 모델링된다.

### 작살

캡슐 발사체다. 충돌 **직전**의 법선 속도가 임계값 이상이고 입사각이 허용각 이내면 관통해 고정 제약이 생기고,
아니면 반발한다. 충돌 후 속도를 쓰면 이미 반발된 값이라 판정이 틀린다.
테더는 대상 둘레에 감길 수 있도록 질점 체인으로 모델링하며, 고정부에 걸린 힘이 한계를 넘으면 이탈한다.

### 테더 윈치 (그물·작살 공통)

결합이 성립하면 테더 자유 길이를 일정 속도로 줄여 장력을 유지한다.
장력 × 모멘트 암이 대상에 감속 토크가 되고, 반작용으로 서비스 위성이 회전해 상대 각속도가 줄어든다.
각운동량은 계 전체에서 보존된다. 장력은 상한을 두어 고정부 파손과 수치 발산을 막는다.

**이 기구가 없으면 그물과 작살에는 감속 경로 자체가 없다.** 아래 "논문에 반드시 쓸 것"을 볼 것.

### 웹 3D 리플레이 뷰어 (권장)

`--viewer out.html` 을 붙이면 헤드리스로 돌린 뒤 three.js 3D 리플레이가 통째로 들어간 HTML 파일 하나를 만든다.
브라우저에서 더블클릭으로 열리고, PyBullet 이 계산한 궤적을 그대로 재생하므로 시각화가 결과를 바꾸지 않는다.

```bash
python capture_sim.py --method net --target medium --spin 10 --viewer out.html --open
python capture_sim.py --method arm --target large --spin 20 --viewer arm20.html --trajectory arm20.json
```

- **재생**: 재생·일시정지, 타임라인 스크럽, 0.25~4배속, `,` `.` 한 프레임 이동. 접촉·결합·이탈 시점이 표시된다.
- **카메라**: 마우스 드래그 회전, 휠 줌, Shift 또는 오른쪽 드래그 팬, 터치 핀치 줌.
  중점·대상·서비서·자유 네 가지 추적 모드(키 1~4), `R` 리셋.
- **텔레메트리**: 시각, 상대 각속도, 대상 각속도, 거리, 결합 상태, 방식별 상태를 실시간 표시.
- **그래프**: 상대 각속도 시계열에 임계값 선과 결합 유지 구간 음영. 클릭하면 그 시각으로 이동한다.
- 스프링·회전축·파지점·궤적·지구 표시 토글, 스크린샷, 전체화면. `?` 또는 `H` 로 조작법.

지구 텍스처와 three.js 를 모두 내장하므로 인터넷 없이 열린다. 파일은 시행 길이에 따라 1~7 MB 다.

### 웹 배포 (`build_site.py`)

리플레이를 인터넷에 올리려면 자기 완결형 HTML 을 그대로 올리는 대신 정적 사이트로 묶는 편이 낫다.
자기 완결형 파일은 three.js(590 kB)와 지구 텍스처(230 kB)를 파일마다 내장해서 여러 개를 올리면 중복되기 때문이다.

```bash
python build_site.py                 # demo/*.html 로 site/ 생성
python build_site.py --serve         # 빌드 후 http://localhost:8000 에서 확인
python build_site.py --inputs a.json b.html --out site
```

이미 만들어 둔 리플레이 HTML 에서 궤적을 도로 꺼내 쓰므로 **재시뮬레이션이 필요 없다.**
궤적 JSON(`--trajectory`)을 직접 줘도 된다.

```
site/
  index.html          시행 목록 (성공 여부·감속 시간·충격량 요약)
  runs/<이름>.html     뷰어. 공유 자산을 참조한다
  data/<이름>.js       궤적 자료
  assets/              three.min.js, earth.jpg (한 번만 올라간다)
  vercel.json          캐시 헤더
```

**배포 방법 1 — GitHub 연동 (권장).** 저장소 루트의 [vercel.json](vercel.json) 이 출력 폴더를 `site/` 로
지정해 두었으므로, Vercel 에서 이 저장소를 Import 하면 별도 설정 없이 배포된다. 빌드 명령도 필요 없다.
이후 `git push` 할 때마다 자동으로 다시 배포된다.

이 방식은 **`site/` 가 저장소에 들어 있어야 동작한다.** Git 연동 배포는 저장소에 있는 파일만 올리기 때문이다.
그래서 `site/` 는 생성물이지만 예외적으로 git 추적 대상에 둔다. 리플레이를 새로 만들었다면
`python build_site.py` 로 다시 빌드한 뒤 커밋해야 배포본에 반영된다.

**배포 방법 2 — CLI 직접 배포.** 저장소와 무관하게 로컬 폴더를 바로 올린다.

```bash
npx vercel --cwd site           # 미리보기 URL 발급
npx vercel --cwd site --prod    # 운영 URL 발급
```

Netlify(`npx netlify deploy --dir site --prod`)나 GitHub Pages 처럼 정적 파일을 그대로 서빙하는 곳이면
어디든 같은 방식으로 올라간다. 서버 코드가 없어 무료 플랜으로 충분하다.

빌드에는 물리 엔진이 필요 없다. `build_site.py` 는 `capture_sim` 을 불러올 수 없는 환경에서도
궤적 자료에 들어 있는 값으로 대신 동작하므로, PyBullet 이 없는 배포 서버에서도 실행할 수 있다.

`index.html` 은 검색 엔진이 수집할 수 있는 공개 페이지가 된다. 발표 전에 공개하고 싶지 않다면
Vercel 프로젝트 설정에서 비밀번호 보호를 걸거나 미리보기 URL 만 공유할 것.

## 수치 검증

```bash
python run_verification.py              # 전체
python run_verification.py --only dt    # 시간 스텝 수렴만
```

1. **토크-프리 회전**: 비대칭 관성체의 세차 운동을 오일러 방정식 RK4 기준해와 비교한다.
   20 초 후 각속도 상대 오차 7.2e-4, 각운동량 상대 오차 7.5e-4 로 통과했다.
2. **시간 스텝 수렴성**: dt 를 1/480, 1/960, 1/1920 으로 줄여 가며 지표가 수렴하는지 본다.
   접촉이 있는 다물체 시뮬레이션은 스텝을 바꾸면 접촉 순서가 달라져 완전히 같아지지 않으므로,
   성공 판정이 뒤집히는지와 충격량이 같은 자릿수인지를 근거로 제시한다.

   그물의 스프링 계수는 안정조건에서 dt 로부터 유도되므로(`k = f·m/dt²`), dt 를 바꾸면 모델 자체가 달라진다.
   실제로 dt 를 절반으로 줄이면 강성이 4배가 된다. 그래서 이 시험은 `net.spring_reference_dt` 로
   계수를 기준 dt 값에 **고정해 두고 적분 스텝만** 바꾼다. 그러지 않으면 수렴성을 볼 수 없다.
   기준보다 큰 dt 는 안정조건을 넘으므로 자동으로 제외된다.
3. **충격량 측정 일관성**: 운동량 변화 누적과 접촉력 적분을 비교한다.

결과는 `verification/verification_report.txt` 에 정리된다.

## 방식 간 통계 비교 (`analyze_compare.py`)

격자 실험은 같은 반복 번호에 모든 조합이 같은 시드를 쓰도록 설계되어 있다(공통 난수).
따라서 같은 (대상, 회전 속도, 시드)에서 나온 두 방식의 결과는 **짝지어진 관측**이고,
짝지은 검정을 쓰면 시드에서 오는 변동이 상쇄되어 훨씬 작은 표본으로도 차이를 가릴 수 있다.

조합별 신뢰구간만으로는 "로봇팔이 그물보다 유의하게 낫다"를 말할 수 없다. 이 분석이 그 부분을 채운다.
추가 시뮬레이션 없이 기존 격자 자료만으로 수 초 만에 끝난다.

```bash
python analyze_compare.py
```

| 검정 | 대상 지표 | 쓰는 이유 |
|---|---|---|
| McNemar 정확검정 | 성공 여부 | 불일치 쌍만 쓰는 짝지은 이진 검정 |
| 짝지은 부트스트랩 | 성공률 차이 | 효과 크기와 95 % 신뢰구간 |
| Wilcoxon 부호순위 | 잔류 상대 각속도 | 연속 지표라 성공에 못 미친 차이까지 잡는다 |

방식쌍 3개 × 대상 3개로 검정이 여러 번이므로 Holm-Bonferroni 로 보정한 p 값을 함께 낸다.
회전 속도별 표(`compare_by_spin.csv`)는 탐색용이며, 결론은 대상별 통합 결과로 말하는 편이 안전하다.

출력은 `comparison/` 에 쌓인다. `method_ranking.csv`(대상별 순위와 1위·2위 유의성),
`compare_by_target.csv`(주 결과), `compare_by_spin.csv`(탐색용), `comparison_report.txt`(사람이 읽을 표).

검정 자체는 차이를 심은 합성 자료로 복원되는지, 차이가 없는 자료에서 거짓 양성이 없는지 둘 다 확인했다.

## 논문에 반드시 쓸 것

아래는 결과를 크게 좌우하므로 방법론 절에 명시해야 한다. 모두 짧은 시행만으로는 드러나지 않고
격자를 실제로 돌려 보고서야 발견한 것들이다.

**1. 테더 윈치가 그물·작살의 유일한 감속 기구다.**
윈치 없이 테더를 느슨하게 두면 인장 전용 스프링이 끝까지 힘을 내지 않는다.
실제로 초기 설정(자유 길이 15.7 m, 도달 거리 12.4 m)에서는 테더가 한 번도 팽팽해지지 않아
그물과 작살이 회전 0 을 빼면 전부 실패했다. 강성을 4배, 감쇠를 16배 올려도 결과가 소수점 둘째 자리까지
같았던 것이 그 증거다. 테더 길이를 교전 거리에 맞추고 정장력 윈치를 넣은 뒤에야
세 방식 모두 조건에 따라 성공과 실패가 갈리는 의미 있는 비교가 되었다.

**2. 테더 감쇠가 부족하면 대상이 테더에 매달려 계속 진동한다.**
작살은 감쇠 5 N·s/m 에서 3.7 deg/s 에 머물렀고, 30 N·s/m 에서 126 초에 성공했다.
명시적 적분의 안정조건 `c·dt/m < 0.5` 때문에 감쇠를 키우려면 테더 질점 질량도 함께 키워야 한다.

**3. 그물 질량은 크기에 비례해야 한다.**
질점 질량을 고정했을 때 2 m 그물이 7.9 kg 이었다. 10 kg 소형 대상의 79 % 무게로,
포획이 아니라 대상을 쳐서 날려버려 소형 성공률이 0 이 나왔다.
면밀도로 바꾼 뒤 그물 질량은 대상 질량의 3.9 % / 0.95 % / 0.12 % 가 되었다.

**4. 시간 창은 180 초다.**
테더 방식의 감속은 100 초 규모라 60 초 창에서는 비교가 성립하지 않는다.
로봇팔은 1~3 초에 끝나므로 **이 연구의 핵심 지표는 이진 성공 여부보다 감속 소요 시간**이다.

**5. 기본 회전축은 접근축에 수직인 z 축이다.**
중형 대상은 태양전지판이 접근 평면을 쓸고 지나가므로 로봇팔에 불리하다.
회전축을 x 로 두면 파지점이 회전축 위에 온다. 본 격자는 z 축으로 돌리고,
회전축의 영향은 민감도 분석에서 따로 정량화한다.

민감도 분석에서 회전축의 합산 영향은 하위권이었지만, **대상별로 보면 중형에서 결과가 달라진다.**
x 축 회전에서는 중형 대상에 대한 그물의 성공이 6 회 중 4 회에서 2 회로 줄어 세 방식이 비슷해졌다.
합산 지표에서는 영향이 거의 없는 소형·대형에 중형의 변화가 희석되어 보이지 않았다.
따라서 **"중형은 그물이 유효하다"는 결론은 접근축 수직 회전에서만 확립된 것**으로 적어야 한다.

**6. 작살 고정부 파단 판정이 적분 간격에 의존하는 결함이 있었고, 고쳤다.**
작살이 박히는 순간 한 스텝 안에 상대 운동을 멈추게 하면 제약력이 운동량/dt 가 되어, 같은 충돌도 dt 를 줄이면
힘이 커져 고정부가 뜯겼다. 격자의 작살 1,440 회 중 86 회가 이 인공물로 실패로 집계되어 있었다.
관통을 유한한 감속력(1,500 N, 약 2.4 cm)으로 바꿔 수정하고 작살 전체를 다시 계산했다.
**성공 시행 수는 수정 전후 모두 189 회로 같았다.** 뜯겼던 시행의 대부분이 고정이 유지돼도 감속에 실패했기 때문이다.
결함이 개별 궤적에는 영향을 주었으나 성공률 통계는 흔들리지 않았다는 점을 방법론의 신뢰성 근거로 쓸 수 있다.
수정 전 원자료는 `results/archive/` 에 보관해 두었다.

**7. 주 지표는 회전 대상(2~30 deg/s)의 성공률이다.**
정지 대상은 붙잡는 순간 이미 상대 각속도가 0 이라 감속할 회전이 없으므로, 성공률이 결합 능력만 반영한다.
특히 작살은 정지 대상에서 중형 80 %, 대형 100 % 였으나 2 deg/s 만 돌아도 3 %, 30 % 로 급락해,
전체 성공률(대형 11.2 %)과 회전 대상 성공률(5.3 %)이 크게 다르다.

## 기존 우주 환경 시뮬레이터를 쓰지 않은 이유

Basilisk(Vizard), Orekit, GMAT 같은 우주 환경 도구는 궤도·자세 역학과 시각화에 특화되어 있고
로봇팔·그물·작살의 접촉 및 다물체 역학을 지원하지 않는다.
반대로 PyBullet, MuJoCo, Gazebo 같은 물리 엔진은 접촉은 잘 다루지만 궤도 환경이 없다.
포획 순간 연구에서는 접촉 물리가 핵심이므로, 물리 엔진 위에 궤도 환경의 유효 효과
(무중력, 토크-프리 회전, CW 상대 역학, 중력구배)를 직접 얹는 구성을 택했다.
